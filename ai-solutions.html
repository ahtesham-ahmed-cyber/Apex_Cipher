Assistants and agents built for real tasks

We build generative AI systems that operate against a defined task, with ground-truth they can be measured against, guardrails appropriate to the consequences of being wrong, and human oversight where it matters. The goal is a system people choose to use because it works, not because it is novel.

Our approach

Task first, model second

Model choice is the most visible part of a generative AI system and the least important to get right first. Before we look at models we define what the task is, what counts as a correct answer, where the source material comes from, and what happens when the system is uncertain or wrong.

That work shapes the architecture far more than the model version. It also produces the evaluation set that lets us measure quality honestly across releases, providers, and future model changes.

Task What has to be produced, for whom
Ground truth Sources, retrieval, freshness
Evaluation Test set, scoring, regression checks
Oversight Review points, traceability, limits

The order in which we work through a generative AI problem. Model selection sits inside “Ground truth” and is revisited as evaluation reveals what matters.

What we build

Four families of AI system

These are the shapes most generative AI engagements take. Most projects combine one or two, and every one of them runs through the same evaluation and oversight practices described on this page.

01 — Retrieval

Retrieval-augmented assistants

Systems that answer questions grounded in your own documentation, tickets, and internal knowledge, with sources the reader can verify.

Content pipeline

Ingestion, chunking, and refresh that keeps the index aligned with the source of truth.

Retrieval quality

Hybrid search and reranking tuned against the actual questions users ask, not a synthetic benchmark.

Citations & provenance

Every answer points back to the passages it drew on, so readers can check the reasoning themselves.

Abstention behaviour

The assistant says it does not know when it does not, rather than producing a plausible-sounding answer.

02 — Agents

Agent workflows

Multi-step tasks with explicit scope, minimal tool access, and human checkpoints where the action has consequences.

Task decomposition

Breaking a workflow into steps that can be evaluated and controlled individually.

Tool design

Narrow, well-described tools with the least privilege required for the task.

Human checkpoints

Defined review and approval points, with the reasoning recorded so the decision is auditable.

Failure handling

Retries, escalation paths, and clear behaviour when the agent cannot complete a step.

03 — Workflows

Intelligent workflows

Where AI components fit into existing processes — classification, extraction, summarisation — without replacing the systems around them.

Classification

Routing, tagging, and prioritisation where the label set is stable and the cost of error is understood.

Extraction

Structured data pulled from unstructured documents, with confidence scores and review queues.

Summarisation

Consistent summaries of long inputs, with the source retained for verification.

Process integration

AI steps that plug into existing workflow tools and queues rather than requiring a new interface for every task.

04 — Quality

Evaluation, guardrails & observability

The practices that turn a working prototype into a system the business can rely on, and keep it reliable as models and prompts change.

Evaluation sets

Task-specific test cases curated with domain experts, versioned alongside the code.

Regression checking

Automated scoring on every change so quality shifts become visible before users encounter them.

Input and output constraints

Schema validation, content filters, and rate limits applied where the task requires them.

Trace logging

Records of inputs, outputs, and intermediate steps so incidents can be diagnosed and reviewed.

Fit

Tasks where generative AI earns its place

Generative AI is not the right tool for every problem. These are the patterns where we have seen it genuinely help, and the patterns where we steer clients elsewhere.

Choosing the right problems

The strongest generative AI projects share a set of properties: a defined task, available ground truth, tolerance for review, and a measurable outcome.

Strong candidates

  • A task that is currently done by people reading long inputs and producing short summaries.
  • Answers that can be verified against a source the reader already has access to.
  • Workflows where a first draft saves time and a human reviews before use.
  • Classification or extraction tasks with a stable, agreed label set.
  • Internal knowledge retrieval where the corpus is authoritative and searchable.

Better solved another way

  • Deterministic rules that can be written explicitly and tested.
  • Numeric computation where the correct answer is a single value.
  • Tasks where any error is unacceptable and no human review is possible.
  • Problems with no reliable source of truth for the model to draw on.
  • Use cases whose success cannot be measured, even retrospectively.

Delivery

From task definition to ongoing operation

Every AI system we build follows the same sequence. Evaluation is not an afterthought; it shapes what the first release looks like and how the system is improved once it is running.

  1. 01

    Define

    Agree the task, the acceptable output, the source material, and the human review points before any model is chosen.

  2. 02

    Evaluate

    Build a small, expert-curated test set that scores the current best approach and will continue to score every change.

  3. 03

    Build

    Implement retrieval, orchestration, and the interface, running the evaluation set on every increment.

  4. 04

    Operate

    Trace logging, review queues, and a clear owner so quality can be observed and improved after launch.
